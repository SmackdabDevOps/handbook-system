# Husky Git Hooks - Handbook System Templates

This directory contains template git hooks for handbook-system projects. These hooks enforce code quality, test coverage, and validation freshness standards.

## Overview

The handbook-system provides two git hooks:

1. **pre-commit** - Runs before every commit to enforce:
   - Lint & format checks (via `lint-staged`)
   - Test coverage for staged files (90% threshold)
   - TDD validator freshness

2. **commit-msg** - Runs after commit message is entered to validate:
   - Validation artifacts are fresh (not stale)

## Installation

The `handbook-init` script automatically installs these hooks:

```bash
npx handbook-init
```

This command:
1. Copies hook templates to `.husky/` in your project
2. Runs `npx husky install` to activate hooks
3. Customizes paths based on `handbook.config.json`

## Configuration

Customize hook behavior via `handbook.config.json`:

```json
{
  "hooks": {
    "coverage_check_path": "scripts/validation/check-staged-coverage.ts",
    "commit_guard_path": "scripts/validation/commit-guard.ts",
    "freshness_check_path": "scripts/validation/check-registry-freshness.ts"
  }
}
```

These paths are injected as environment variables:
- `COVERAGE_CHECK_PATH` - Used by pre-commit hook (Step 2)
- `COMMIT_GUARD_PATH` - Used by pre-commit hook (Step 3)
- `FRESHNESS_CHECK_PATH` - Used by commit-msg hook

## How Hooks Work

### Pre-Commit Hook

Runs three sequential checks:

**Step 1: Lint & Format** (via `lint-staged`)
- Lints staged files using ESLint
- Auto-fixes formatting issues
- Blocks commit if errors remain

**Step 2: Test Coverage** (via `COVERAGE_CHECK_PATH`)
- Checks that staged files have 90%+ test coverage
- Uses TypeScript validator at configured path
- Blocks commit if coverage threshold not met

**Step 3: TDD Validator Status** (via `COMMIT_GUARD_PATH`)
- Verifies TDD validator passes before commit
- Ensures validation results are fresh
- Blocks commit if validation fails

### Commit-Msg Hook

Validates that validation artifacts are fresh:
- Runs freshness check (via `FRESHNESS_CHECK_PATH`)
- Ensures validators were run recently
- Prevents committing with stale validation results

## Bypassing Hooks

For emergency situations only:

```bash
git commit --no-verify
```

**Never use `--no-verify` for regular development.** These hooks exist to maintain code quality and prevent technical debt.

## Troubleshooting

### Hook not running?

Check that Husky is properly installed:

```bash
test -d .husky || echo "Husky not installed"
ls .husky/                    # Should show pre-commit, commit-msg
```

Reinstall if needed:

```bash
npm install
npx husky install
```

### Lint/format errors?

Fix ESLint issues:

```bash
npm run lint -- --fix
npm run format
```

### Coverage below threshold?

Add tests for staged files:

```bash
npm test -- --coverage
```

Aim for 90%+ coverage on changed files.

### Validation failures?

Run validators manually:

```bash
npm run validation:quick     # Fast checks
npm run validation:all       # Full validation suite
```

See `handbook/validation/` for validator documentation.

## File Structure

After `handbook-init` runs, your project will have:

```
.husky/
├── pre-commit          # Copied from templates, customized
├── commit-msg          # Copied from templates, customized
├── .gitignore          # Auto-generated by Husky
└── _/
    └── husky.sh        # Husky helper script
```

## Best Practices

1. **Run tests locally before committing** - Don't rely solely on the hook
2. **Keep validation scripts updated** - Sync with handbook updates
3. **Review hook failures carefully** - They protect code quality
4. **Use `--no-verify` sparingly** - Only for genuine emergencies
5. **Update `handbook.config.json`** - When changing validator paths

## Template Notes

These are **templates** managed by handbook-system. When you run:

```bash
npx handbook-init
```

The hooks are customized for your project based on `handbook.config.json`. Do not manually edit `.husky/` hooks—instead:

1. Update paths in `handbook.config.json`
2. Re-run `npx handbook-init` to regenerate hooks

This ensures all projects stay in sync with handbook standards.
